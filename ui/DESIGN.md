# Design notes

How the web UI looks and moves, and the reasons behind it.

## A lab notebook

margin's agents show their work. They read code, mark the evidence and weigh it for and
against, so the UI looks like that kind of work: warm paper, dark ink, and a highlighter for
the parts that matter.

The logo is a page of notes in an ink-coloured tile with one line highlighted. The
highlighter shows up wherever something deserves attention: the key phrase on the home page,
the page you're on in the navigation, the stage a run is at, text you select, and lines of
evidence. Behind the two big panels there's a faint dot grid, like notebook paper, and the
illustrations are sheets of paper with warm shadows.

margin is a library of agents, so the home page shows a stack of index cards, one per
installed agent, and cycles through them. A new agent gets a card without anyone touching
the page, and no agent is featured over the others. An agent can still tell its own story
on its own page. The AI Code Detector does, with a sheet of code that has two lines marked
and a note in the margin beside each, one for and one against.

Code is drawn as a "minimap": rounded bars, indented the way code is. During a run, a
highlight moves down it line by line, the way the agent reads a file.

## Principles

We learned a lot from good product design, including the research behind Google's Material 3
Expressive. We took the principles from it, never anyone's brand: no other company's logo,
logo colours, typefaces or recognisable details.

Most of the UI is plain on purpose. Only two places get the full treatment: the home page
(headline, launcher, card catalogue) and a run in progress (the wavy progress line and the
reading minimap). Lists, forms and results stay quiet.

Animation has to earn its place. It shows where something came from, or that work is going
on, and nothing moves just to look nice. Springs settle with a small overshoot, and with
`prefers-reduced-motion` turned on, the motion goes away.

Containers are shades of paper rather than boxes with borders; a thin line appears only
where two things need separating. Text is in sentence case, icons come with labels, and
evidence is real text in a monospace font, so you can select and copy it.

## Tokens

Everything lives in `src/styles/`.

Colours are generated by `scripts/gen-theme.mjs` using `@material/material-color-utilities`,
from three palettes: a deep ink teal (HCT hue 186), a highlighter amber (hue 84) and warm
paper greys (hue 95, chroma 4). The script writes `theme.css` for light and dark mode, plus
`--marker` and `--marker-strong` for the highlighter.

Headings use Fraunces with its "soft" axis turned up, so it reads friendly rather than
academic. The interface uses Instrument Sans, and code and evidence use JetBrains Mono. All
three fonts are bundled with the UI (SIL Open Font License).

Icons are Phosphor, in the regular weight, with the duotone style for the navigation item
you're on. `src/components/icons.ts` lists every icon the UI uses.

Corner radii come from a fixed scale (4, 8, 12, 16, 20, 28, 32, 48 and fully round), and agent
avatars are tiles rounded at 30%. The easing curves are `cubic-bezier(.2,0,0,1)` for most
transitions and `(.05,.7,.1,1)` for things arriving on screen. The springs (fast, default and
slow, damping 0.6 to 0.8, plus non-bouncy ones for colour and opacity) are generated as CSS
`linear()` curves.
